# Linear, for a complete beginner — and exactly how we use it here

**Written 15 October 2026.** Covers Linear itself, then your actual workspace: team **PRE**, projects, the 37
issues created today, the labels, and the daily habits that keep it useful.

If you read only one section, read **§4 (the five-minute morning routine)** and **§5A (start working on
something)**. Everything else is reference.

---

## 0. What Linear is, in 60 seconds

Linear is a **task tracker for teams** — a shared list of work where every item has an owner, a state and a
history. It is the tool used for "what are we doing, who is doing it, and where has it got to".

It is deliberately fast and keyboard-friendly. You do not have to learn all of it. Four screens cover 95% of
everything you will ever need:

| Screen | What it is for |
|---|---|
| **My Issues** (left sidebar) | Everything assigned to you, across all projects |
| **A project** (e.g. *Branding & Decoration Botswana — Orchestrator Launch*) | The whole programme: progress, milestones, every issue |
| **An issue** (click any PRE-number) | One piece of work: description, discussion, status |
| **Search** (`/`) | Find any issue, project or comment by word |

## 2. Six words and you are fluent

1. **Workspace** — the whole account (yours is `PressCafeWorld`). One workspace holds everything.
2. **Team** — a group that owns issues and gives them their prefix. You have **one team: `PressCafeWorld`,
   prefix `PRE`**. Every issue you make is therefore `PRE-something`.
3. **Project** — a container with a start, a target date and a status. You have two (see §3). A project is
   *not* a team: the same team can run several projects.
4. **Issue** — one unit of work: *"Open Amrod Botswana trade account."* This is the atom of Linear. An issue has
   a title, a description, a status, a priority, an assignee, labels and comments.
5. **Sub-issue / parent** — an issue can hang under another. We use **five parent issues as phase milestones**,
   with the delivery tasks nested underneath.
6. **Label** — a cross-cutting tag (ours: `supply`, `commercial`, `compliance`, …). Labels let one issue serve
   two purposes: it sits in its phase *and* shows as supply work.

### Two different things both called "status" — do not confuse them

| | Values | What it means |
|---|---|---|
| **Issue status** | `Backlog` → `Todo` → `In Progress` → `In Review` → `Done`, plus `Canceled` | Where one task is |
| **Project status** | `Backlog` → `Planned` → `In Progress` → `Completed`, plus `Canceled` | The overall health of the programme (ours is **In Progress**) |

**Priority** runs 1 → 4 on the scale `Urgent · High · Medium · Low` (0 means "no priority set"). In your
workspace: **1 = do it first, 2 = soon, 3 = when the first two are moving, 4 = parked on purpose.**

## 4. The five-minute morning routine

1. Open Linear → left sidebar → **My Issues**. These are yours. Nothing else needs your attention first.
2. Pick the **highest priority (1)** item that is not Done.
3. Move it to **In Progress** (click the status icon on the left of the row, or press `S` while it is selected).
4. Work it. When something worth remembering happens — a price quoted, a person spoken to, a document
   received — **put it in the issue as a comment** (§5B). A task without its history is just a reminder.
5. When it is finished, mark it **Done** and write one line: what the outcome was, and what it now unlocks.
6. Once a week (Friday, 15 minutes): open the **project**, check the progress bar, and look for anything sitting
   in `In Review` for more than two days. That is the backlog of other people's delays — chase it.

## 5. Walkthroughs

### A. Start working on something
1. Left sidebar → **Projects** → *Branding & Decoration Botswana — Orchestrator Launch*.
2. Click **PRE-17** (Amrod trade account) — or type `PRE-17` in search.
3. Click the **status chip** on the left (it says *Todo*) → choose **In Progress**. The issue now shows in your
   My Issues list as active.
4. Read the description. It tells you the Do, the "Done when", and why it matters. Work from that — no guessing.

### B. Record what happened (the single most valuable habit)
1. Open the issue → scroll to the bottom → click the **comment box**.
2. Type what happened, plain and factual. Include numbers and dates. For example:
   > *15 Oct — Amrod Botswana replied. Trade account form sent. Tier pricing promised within 5 working days.
   > Contact: [name], [email]. Needs CIPA certificate + VAT certificate to open the account.*
3. Press **Enter** to save. Use **Ctrl/⌘ + Enter** only if your workspace is set that way — otherwise Enter
   saves and a new line needs Shift+Enter.
4. Stick to **facts and dates**, not feelings. Six months from now this comment is the memory of the business.

### C. Finish something
1. Set the status to **Done**.
2. Add one line: the outcome and the consequence — *"Landed cost confirmed at P189/unit duty-paid; modelled
   cost was P205, so pricing rules updated in `data/catalogue.json`."*
3. If it produced a document, link it (§5G).
4. Never mark something Done if a sub-step is unfinished — make the unfinished part a **new issue** instead.

### D. Add something you discovered
1. Press **`C`** (new issue).
2. **Title convention:** a verb and a thing — *"Collect three quotes for hi-vis vest supply"*, not *"vests"*.
3. Fill in: **Team** (PRE) → **Project** (ours) → **Parent issue** (whichever phase it belongs to) →
   **Priority** → **Label(s)** → **Assignee** (you).
4. In the description paste the same three lines every issue here uses:
   - **Do:** the action
   - **Done when:** the test
   - **Ref:** the document or backlog ID (e.g. `docs/04` · BDB-011)
5. A new issue gets the next free number automatically (PRE-49 and so on).

### E. Find anything
- `/` → search everything by word.
- **Filter** (top of any list) → by `Label` = `commercial`, or by `Parent issue` = `PRE-12`, to see one phase
  at a time.
- `Ctrl/⌘ + K` → the command menu: jump to any issue, project or setting without hunting through menus.

### F. See how the programme is going
Open the project. You get: a **progress bar** (share of issues Done), the **milestones** (our parent issues)
with their own completion, and every issue grouped by status. That page is the honest answer to "where are we?"
— which is why statuses must be truthful.

### G. Attach a file, safely
Linear hosts files, but **do not put client or worker personal data in here** (Data Protection Act 2024
discipline: minimise, restrict, keep a Botswana-resident copy). Instead:
1. Put the document in Google Drive, in a folder shared only with the people who need it.
2. Copy the Drive link → paste it into the issue comment. The task keeps the pointer; Drive keeps the file;
   access stays controlled.

### H. Fix a mistake
- Wrong column? Change the status — nothing is ever lost.
- Wrong project or parent? Open the issue → move it to the correct project via the project field. History follows.
- Created it by accident? **Archive it** (the `⋯` menu on the issue → Archive). Archive is reversible: open
  **Settings → Archive** (or search the archive) and restore it.
- **Delete is permanent.** Linear warns you first. For a new user, the rule is simple: **archive, never delete.**

### I. On your phone
Install the **Linear** app (iOS/Android), sign in with the same account, and turn on notifications for
assignments and comments. Use it for reading and for quick comments from the road — most of your supplier
visits will produce notes you would otherwise lose. Do detailed editing on a computer.

## 7. House rules for this workspace

1. **One project per business.** B&D Botswana work goes in the B&D project; EverythingCity work stays in its
   own. Mixing them destroys the reporting.
2. **Every issue has a phase parent.** If you cannot say which phase it belongs to, it is probably not work yet
   — put it in the Notion Decision Log instead.
3. **Statuses tell the truth.** `In Progress` means you are working on it this week. `In Review` means you are
   waiting on someone else — say who, in a comment.
4. **No secrets, no personal data.** No client employee lists, no ID numbers, no bank details, no passwords.
   Worker size matrices and contact details live in the operational system, not in Linear.
5. **Comments are for facts.** Decisions with consequences go to the Notion **Decision Log** and get linked
   from the issue.
6. **Archive, never delete.**
7. **Don't rename the team key `PRE`.** Issue URLs (`PRE-17`) depend on it, and links in our documents would break.

## 9. Plain-English glossary

| Word | Means |
|---|---|
| **Issue** | A task |
| **Sub-issue** | A task hanging under another task |
| **Backlog** | Sitting in the pile, not scheduled |
| **Todo** | Chosen, not yet started |
| **In Progress** | Actively being worked |
| **In Review** | Finished my part; waiting on someone or something to confirm |
| **Done** | Finished and evidenced |
| **Canceled** | Deliberately not doing it (say why in a comment) |
| **Assignee** | The person responsible |
| **Label** | A tag across projects |
| **Cycle** | A time-boxed sprint (we are not using them) |
| **View** | A saved filter arrangement |
| **Archive** | Put away, restorable |
| **Milestone** | A checkpoint inside a project (we use parent issues) |

## 10. If you get stuck

- In Linear: `?` or the **Help** item opens the built-in guide, and `Ctrl`/`⌘` + `K` will find any command by
  name ("archive", "assign to me", "create project").
- Linear's own documentation is at **linear.app/docs** (public, no login needed).
- In this workspace specifically: everything is reversible except **Delete**. If you are unsure, stop and ask —
  I can move, re-label, archive or restore issues for you, and the Notion command centre links straight to the
  project.

**Nothing in Linear is precious enough to be scary. The only real mistake is a status that is not true.**
